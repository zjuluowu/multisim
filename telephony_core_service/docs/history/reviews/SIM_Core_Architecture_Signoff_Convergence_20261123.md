## 决策记录

以下三项先从原业务和反例确定约束，随后映射到四篇文档。签收指设计有明确实施和验收口径。产品行为变化仍需相应责任方批准。

### SC-01　关闭时谁接走未完成的工作

- **现状与发现。** A 持 Primary 角色资格和原结果，O 为 A 保存步骤和一次完成出口，R 查设备，Scheduler 查队列，H 判定关闭。C0 无设备请求。ICCID 已写、写调用完成性未知时，原调用完成数为 0、角色仍在切换，H 返回 Drained。
- **决定与分责。** A 对每个已受理请求交代原出口和每一项已发未确认的存储效果。O 记录领取及交付进度，实际回调返回由交付侧证明。Scheduler 报关门、已投递与在执行工作。R 分报向 Owner 交付及物理资源。H 在同一已封口实例汇合这些收据，不能替任何一方消账。受理者移交给有寿命保证的常驻接收者时，须确认原引用、写资格、旧关联、原完成出口、唯一接手人和不能绕过的隔离均已接管。没有此能力时原图留存。
- **兼容与禁止。** 保留原返回、一次完成和参数/通知偏序。禁止清 pending、伪造回调、把 R 空闲或 deadline 当作完成。无产品证据不承诺进程崩溃后补发回调。
- **验收与依赖。** 分别注入 ICCID 已写未确认、未写未确认，Stop 两次都须报告未完且不得重复写、回调或退资格。提供可区分的原存储证据后完成原交付，或由常驻接手者确认并负责最终核对。验证拒收、晚证据、正在回调及 Owner 自身请求关闭。产品须证明接手人存活、旧句柄封口与其它 RIL 消费者连续性。

### SC-02　只向本轮协议的可路由参与者发令

- **现状与发现。** T 签发订阅绑定，R 的卡会话由卡运行签发。已提交的 A 用绑定版本合成 USIM 会话，C1 遍历目录，在仅有两个可路由栈的四端点夹具中发出四个 CHECK。
- **决定与分责。** R 的协议适配依据已验证的产品协议、栈和实际路由给出本次参与者与资源范围。H 提供静态配置。A 选择业务目标，固定计划和每轮步骤。R 在首次副作用前验证可执行性，按原生协议会话、阶段、成员及每次发送的传输关联匹配结果。BindingRef 约束业务目标，CardApplication Session 只供真正访问应用的步骤使用。成员映射变化使旧计划待核对，不能在途增删成员。
- **兼容与禁止。** 保持旧双栈三阶段、原错误/重试/恢复及进度通知。不得按可见槽数推定协议成员、编造路由或用 bindingRevision 签发应用会话。若必需成员缺路由，首次副作用前选择已验证旧路径；只有原契约或经批准的错误可向外拒绝。已经发令或预写后禁止改走第二个执行器。
- **验收与依赖。** 双卡复用原 Legacy/Target Oracle；四端点两栈仅向协议指定的两成员发令，缺必需路由、过期会话、重复成员、错阶段、错误传输及在途换路分别设反例。新多栈、特殊槽政策和 HDI 结束/复用证据由各产品给出。

### SC-03　写资格跟随实际参数或数据库列

- **现状与发现。** C1 持有包含偏好键的写集时，独立的 Profile 提示仍能把 false 写成 true。Core 两入口与 eSIM 切换落同一个旧参数。Disable 的有槽后缀和无后缀参数、探测和运营商直接写库、号码查询后台回写属于另外的字段及触发点。
- **决定与分责。** 每个物理参数键或 DB 行身份与列由一个业务 Owner 管写入准入。A 管角色与偏好，T 管账户资料和恢复提示，R 管卡及设备效果，I 执行原存储操作。相交写集由同一 Owner 在首次写前串行准入，父请求复用已有资格，独立提示不能借另一请求的身份。联合建行由各 Owner 给出字段计划，沿用一次原写。初始化读取、投影、真实参数写和恢复写分开追溯。
- **兼容与禁止。** 保留 Core 各自前置检查、有效 Profile File 调用返回后的偏好提示（包括内层失败）、Disable 前后置时点、getter 后台回写和原通知。禁止静默丢提示、改变外层返回、以新旧各写一次过渡或用全局写锁串行化独立角色。遇冲突若原契约无法观察等价，保留原路径并单列行为裁决。
- **验收与依赖。** 先扫描键别名、Provider 写、事件/重试、初始化与后台入口，再比对参数序列、两层返回、通知和次数；用 C1×Profile、独立 Data 与无交集 Voice/SMS 验证互斥范围。外仓 writer、Provider 实际列、产品 Feature 与冲突时延尚待取证。
